# 纯软件系统开发手册

面向手机 App、网站、PC 软件和配套后端的独立开发手册，当前版本 **v1.0**。

本仓库专门管理纯软件开发，完整定义角色、架构、工作包、开发环境、代码质量、验收、发布与维护规则。

## 阅读与使用

- [纯软件系统开发手册](index.html)：17 个章节，完整规则的唯一维护源。
- [项目执行约定模板](templates/software-project.md)：可直接在 GitHub 阅读和复制，填写项目实际信息后采用。
- [完整功能工作包表单](templates/github-work-package.yml)：可复制到产品仓库的 GitHub Issue 表单；已有 Issue 直接续写。
- 克隆或下载本仓库，在浏览器打开 `index.html` 即可阅读完整排版；无需安装依赖。GitHub 的 HTML 文件页显示源码。
- 本仓库保持私有，未启用公开网页托管。手册发布不等于任何具体项目已经采用。

## 内容

- P 需求、A 架构与交付、B UI/UX、C 主软件工程师、D 独立质量及可选 E 独立模块职责。
- 按业务划分模块，明确视图、用例、领域规则、外部适配和组合入口的依赖与所有权。
- Q1–Q6 代码原则：高内聚、低耦合、所有权、失败恢复、简洁复用及真实跨模块验证。
- 接口、数据、权限、缓存、并发、迁移与兼容性。
- 开发、联调、生产统一配置入口；区分构建模式与运行环境，使用明确的本地服务和测试数据推进开发。
- 完整功能工作包、按影响范围验证、有效结果复用和真实 Issue 关闭条件。
- 构建、CI、安装升级、部署、回滚、监控、备份恢复、隐私与依赖许可。
- Flutter＋后端、静态官网、Electron 客户端三类示例。

## 维护规则

1. 通用纯软件规则只在 `index.html` 维护；README 保留入口与摘要，模板保留需要实际填写的内容。
2. 调整规则时同步本文档版本、相关章节与模板。项目明确采用版本和生效工作包，保留原始失败及未完成项。
3. 检查差异、UTF-8、本地链接、章节锚点及适用显示；未执行的检查明确标注，不编造通过结果。
4. 不上传产品源码、个人或设备记录、角色聊天 ID、凭据、受限素材或原始业务日志。
5. 普通已授权任务自主执行，复用有效环境与结果；实际影响、失败或证据缺口触发必要的补充检查。
6. 模板不创建角色或项目、不授予外部操作权限；部署、推送等按具体项目既有授权执行，授权范围不变不重复确认。

本仓库为私有内部资料，不因保存于 GitHub 而获得公开分发授权。
